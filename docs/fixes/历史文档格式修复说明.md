# 历史文档格式修复说明

## 问题

历史文档（在添加 `FileExtension` 字段之前导入的文档）该字段值为 `NULL`，前端列表会显示"未知"。

## 解决方案

新增数据修复接口，从 `SourceUrl` 字段推断文件格式并更新。

### API 接口

**端点**: `POST /api/documents/repair-extensions`

**功能**: 批量修复历史文档的文件扩展名

**工作原理**:
1. 查询所有文档
2. 跳过已有 `FileExtension` 的文档
3. 从 `SourceUrl` (格式: `file://filename.ext`) 提取扩展名
4. 更新文档的 `FileExtension` 字段

### 使用方法

#### 方式 1: 使用 curl
```bash
curl -X POST http://localhost:5000/api/documents/repair-extensions
```

#### 方式 2: 使用 PowerShell
```powershell
Invoke-RestMethod -Uri "http://localhost:5000/api/documents/repair-extensions" -Method Post
```

#### 方式 3: 使用浏览器或 Postman
- URL: `http://localhost:5000/api/documents/repair-extensions`
- 方法: `POST`
- 无需请求体

### 响应示例

```json
{
  "success": true,
  "totalDocuments": 150,
  "repairedCount": 85,
  "skippedCount": 65,
  "errorCount": 0,
  "errors": []
}
```

**字段说明**:
- `totalDocuments`: 总文档数
- `repairedCount`: 成功修复的文档数
- `skippedCount`: 跳过的文档数（已有扩展名）
- `errorCount`: 修复失败的文档数
- `errors`: 错误详情（最多显示 10 条）

## 新增代码

### 1. IDocumentService.cs
添加接口方法：
```csharp
Task<bool> UpdateFileExtensionAsync(string id, string fileExtension, CancellationToken cancellationToken = default);
```

### 2. DocumentService.cs
实现更新方法：
- 查询文档
- 更新 `FileExtension` 和 `UpdatedAt` 字段
- 调用仓储层保存

### 3. DocumentsController.cs
添加修复接口：
- 遍历所有文档
- 从 `SourceUrl` 提取扩展名
- 批量更新
- 返回统计信息

## 适用场景

1. **一次性迁移**: 系统升级后首次运行修复
2. **定期维护**: 发现历史数据缺失时手动执行
3. **数据清理**: 确保所有文档格式信息完整

## 注意事项

1. **SourceUrl 格式**: 必须是 `file://filename.ext` 格式才能提取扩展名
2. **批量限制**: 当前限制为 1000 条/次，大数据量需要分批
3. **幂等性**: 可重复执行，已修复的文档会被跳过
4. **无需停机**: 可在服务运行时执行

## 性能优化建议

如果文档量超过 1000 条，可修改代码分页处理：
```csharp
// 修改 ListAsync 调用为分页循环
int pageSize = 1000;
int skip = 0;
while (true) 
{
    var batch = await _documentService.ListAsync(skip, pageSize, cancellationToken);
    if (batch.Count == 0) break;
    // 处理批次...
    skip += pageSize;
}
```

```sql

```
